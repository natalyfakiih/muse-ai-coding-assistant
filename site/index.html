Every programmer remembers the moment. You write your code, you run it, and it doesn't work. So you ask AI, and in seconds you get the answer. The code works.

But did you learn how to solve it, or did you learn how to copy it?

That question is what MUSE is built around. We think AI belongs in education. We just think it should be a tutor, not a code generator.

The question

How do we make AI help students think, instead of thinking for them?

You write your code.
You run it.
It doesn't work.
You ask AI.
The code works, and nothing was learned.

what happens now

The answer arrives before the understanding

A student reads "remove duplicates, preserving order" and starts typing. The assistant finishes it. The tests pass. Nobody ever asked what should happen to an empty list, and the student could not tell you, because the question never came up.

what MUSE changes

The thinking happens first, and it gets written down

The same student says what they want to build before they build it: inputs, outputs, edge cases, one worked example. That document is locked. The finished code is then checked against it, so "I never thought about the empty list" becomes something the student can see and has to explain.

Phase 01 Specification gate

Before a single line of code, say what you actually want to build.

Not code. Your own words. And when something is unclear, MUSE does not assume. It asks. The editor stays locked until you have thought the problem through clearly enough to start.

Enforced The rubric is checked in Python, not asked of the model. An empty examples field cannot be talked into counting as answered.
Guarded Anything the model infers from the assignment rather than from your words is discarded before it is stored, so three rubric items can never tick themselves off a sentence you did not write.
Stuck? "I don't know" explains the question and offers real alternatives to choose between. It never answers it for you.
Escape Asked twice about a genuinely ambiguous point, you can say "my answer stands" and move on. The gate is a teacher, not a bouncer.

Phase 02 Guided implementation

Then comes the code. No autocomplete, no solution waiting to be copied.

The student writes. And when they get stuck, MUSE does not take the problem away from them. Instead of "here is the fixed code", it asks "what value do you expect here?"

Because sometimes the most useful answer is not an answer at all. It is the question that makes you find the answer yourself.

No ghost text The editor runs with autocomplete and inline suggestions switched off. Nothing types ahead of you.
Ask freely A question about Python gets a straight answer. There is nothing pedagogical about making someone guess what enumerate does. A question about your own program gets a question back.
A way out Properly stuck, you can take a direct hint. It is given freely and it is counted. The count is yours to look at, not a punishment.

Phase 03 Reflection

When the code is finished, MUSE looks back at where you started.

What did you say you wanted? What did you actually build? If there is a difference, MUSE does not simply mark it wrong. It asks about it. Now you have to notice it, understand it, and fix it.

Drift Your specification said one thing, your code does another, and nothing in your session shows you noticed.
Revision You changed your mind on purpose. Calling it this requires an actual quote from your conversation. No quote, not a revision.
Bug The code is trying to do what you said and getting it wrong.
Required Nothing is submitted until every difference has an explanation in your own words.

The loop

MUSE turns writing a program into five steps, in that order.

Think

Say what you want to build, in your own words.

Plan

Inputs, outputs, edge cases, one worked example.

Code

You write it. Nothing types ahead of you.

Reflect

Where does the program disagree with the plan?

Improve

Explain each difference, then fix it.

For students

What you walk away with that a finished assignment does not give you.

01

The habit of deciding first

Inputs, outputs, edge cases, one worked example, before a line of code. It is the same discipline behind a design doc, a ticket, an API contract.

02

Edge cases you chose

Empty input, zero, negatives. You decide what happens and write it down, so when your code does something else you can see that it was not your call.

03

Debugging you can do alone

"What value do you expect here?" is the question you will be asking yourself long after the tutor is gone.

04

Words for your own code

Explaining each difference in your own sentences is the part that survives into a code review, a stand up, and an interview.

05

An honest picture of your habits

How many questions you asked, how many were about Python rather than your own program, how many hints you took, how many drafts your plan went through.

06

A record, not a grade

Every draft, question and answer is kept and readable. You can see how your thinking moved, which is the thing a green tick has never shown anyone.

For instructors

Teachers finally get something they have never really had: visibility into how their students are thinking.

Not just who finished. Where they struggled, what they misunderstood, and what the whole class needs to learn next.

Every difference is grouped by the thing it was about, so a misconception the whole cohort shares reads as one row instead of thirty separate mistakes.

Class view Where the class diverged from its own plans. A plain group by, with no AI at read time, so the page is fast and says the same thing twice.
Student view Full plan history, the whole question log with its classifications, and every difference with the student's own explanation.
On demand A written summary of one student's work. It is the only AI call on the dashboard, and it fires on a button, never automatically.
Rubrics Yours. Each item can be a field the system checks in code, or a judgement call, and you set which.

Dependency profile

A mirror, pointed at the student and at nobody else by default.

MUSE counts how you lean on it: total questions, how many were about Python rather than your own program, hints taken, topics you circled back to, how long after opening the assignment you asked for help.

Not a grade It is never part of marking. It exists so you can notice a pattern you would otherwise not see.
Not shared Student facing by default. Instructor visibility is a per course opt in stored in the data model, not a toggle on a page. Without it, the instructor endpoint refuses the read outright.

Under the hood

The rules students rely on are enforced in code, not requested in a prompt.

A model asked nicely not to give away the answer will give away the answer. Everything a student depends on is a check that runs whatever the model says.

Rubric floor

An unanswered structural item counts as unmet in Python before any model is consulted. A weak classifier returning gap: null on an empty plan cannot unlock the editor.

Extraction guard

Fields the model filled in from the assignment text rather than the student's words are dropped, matched back against what was actually typed.

Sandboxed execution

Every test case runs in a fresh subprocess with a wall clock timeout and, on POSIX, CPU, address space and file size limits.

Two providers

Mistral first, Groq on failover, behind a single generate_structured() call. A circuit breaker stops retrying a provider that is rate limiting.

Runs offline

A deterministic stub stands in for both providers, so the whole flow (gate, tutor, reflection) is testable with no API key and no network.

Everything is kept

Every plan version, gate turn, code snapshot, question and difference is a row. The reflection statistics are a query, not a summary.

In short

We don't want AI to become the programmer. We want AI to be the reason the student becomes a better one.

The future of education is not about choosing between humans and AI. It is about making AI work for human learning. MUSE is deliberately worse at the thing other assistants are best at: it will not hand you a function. What it will do is make sure that by the time you write one, you know exactly what it is supposed to do, and that you are the one who decided.
